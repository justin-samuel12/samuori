# Contributing to Samuori

Thank you for your interest. Samuori is created, architected and maintained by Justin Samuel (jsamuel12@gmail.com)
and licensed under the Apache License, Version 2.0 (`LICENSE`, `NOTICE`). By contributing, you agree that your
contribution is licensed under the same terms.

Samuori is pre-release and maintained by one person, so reviews are best effort. For anything larger than a small
fix, open an issue first to agree on the approach.

## Before you start

- Read `docs/README.md` for the documentation map, and `docs/developers/` for the toolchain, Git workflow and releases.
- Check `docs/product/vision-and-scope.md`: Samuori covers discovery, build, test, security, storage, publication and
  promotion of container images, and their administration. It is not a developer portal, source host, general CI
  engine or deployment tool.
- Submit only work you wrote or have the right to contribute. Do not submit code, designs, configuration, tests or
  documentation taken from proprietary material, including an employer's, without authorization.
- Report security vulnerabilities privately as described in `SECURITY.md`, not in issues or pull requests.

## Build and test

You need Go, Node.js and GNU make (versions in `docs/developers/toolchain.md`). Builds of uploaded projects need Linux
with rootless BuildKit; on macOS, use the Lima VM in `deploy/dev/lima/`.

```
make ui-install   # once
make build        # binaries into bin/
make dev          # run the server and UI locally (docs/developers/local-dev.md)
make test         # focused regression tests
make ci           # everything a pull request must pass
```

`make test-vm` runs the Linux-only tests on macOS. Add a focused regression test when you change a security boundary
or a practical workflow (ADR 0039 as amended).

## Developer Certificate of Origin (DCO)

The project uses the [Developer Certificate of Origin 1.1](https://developercertificate.org/) instead of a CLA. You
certify the DCO for a commit by adding a sign-off trailer with your real name and an email you control:

```
Signed-off-by: Your Name <you@example.com>
```

`git commit -s` adds it from your Git identity. Requirements:

- The sign-off must identify the human who certifies the contribution. Tools and AI assistants never sign off and
  never add a sign-off on someone's behalf unless that person explicitly asks for it on that commit.
- Do not use an employer email address or account unless your employer has authorized the contribution.
- Keep existing sign-offs intact when rebasing or amending.

## AI-assisted contributions

AI-assisted development is permitted. Git metadata must name the people responsible, never the tools:

- No `Co-Authored-By:` trailers naming AI assistants.
- No "Generated with ...", "Generated by AI", "Assisted by" or similar signatures, session links or tool footers.
- No AI assistant as Git author or committer; use your own configured identity.
- Pull request descriptions explain the change, rationale, testing and related issues, with no AI-tool commentary.

Check your commit messages and trailers before committing and again before pushing. A DCO `Signed-off-by:` is not
AI attribution and must stay. This policy does not override disclosure or attribution obligations imposed by
external projects or hosting platforms.

## Pull requests

- Branch from `main` as `<type>/<short-topic>` and keep each pull request to one focused change.
- Use [Conventional Commits](https://www.conventionalcommits.org/) for commit and pull request titles; pull requests
  are squash-merged.
- Update the documentation in the same pull request, and add an ADR (`docs/adr/`) for a significant design choice.
- Record any new dependency and its license in `docs/dependencies.md`.
- Follow the code comment standard (ADR 0020) and name YAML files `.yml`.
- Make sure `make ci` passes. Hosted CI is not set up yet, so run it locally.

The full checklist is in `docs/developers/git-workflow.md`, and the pull request template repeats it.
