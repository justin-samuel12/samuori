# 0022. DCO sign-off and no AI attribution in Git metadata

Status: Accepted (2026-10-19, owner decision OD-8 and owner commit policy)

## Context
Contributions need a lightweight certification of origin. The owner chose the Developer Certificate of Origin (DCO)
over a CLA. AI-assisted development is permitted, but Git history must identify the people responsible for changes.

## Decision

### DCO
- Every commit carries a `Signed-off-by: Real Name <email>` trailer for the human who certifies it under the DCO
  1.1 (https://developercertificate.org/), normally added with `git commit -s`.
- A sign-off is a personal certification. Tools, including Claude Code, add it only when the human contributor
  explicitly asks for it on that commit, and always with that contributor's identity.
- The DCO certifies the right to submit under the project's open-source license, Apache-2.0 since 2026-10-27
  ([ADR 0056](0056-apache-2-license.md)). Commits made before the license was chosen may lack sign-off and are
  covered by the owner's decision, not by any tool.
- An automated DCO check is planned for hosted CI, which is not set up yet.

### No AI attribution
- No `Co-Authored-By:` trailers naming AI assistants. No "Generated with ...", "Generated by AI", "Assisted by"
  or similar signatures, no AI session links and no promotional or tool footers.
- No AI assistant as Git author or committer. Commits use the human contributor's configured Git identity.
- PR descriptions explain the changes, rationale, testing and related issues, with no AI-tool commentary.
- Before committing, inspect the message and trailers. Before pushing, verify that no attribution was inserted
  automatically. Correct unwanted attribution before publication without rewriting unrelated or shared history.
- DCO `Signed-off-by:` trailers are not AI attribution and must remain intact.
- This policy does not override disclosure, attribution, licensing or contribution obligations imposed by external
  projects or hosting platforms.

### Identity hygiene
Commits never use an employer email address or domain. The repository sets a local `user.email` when a global
identity is employer-associated.

## Consequences
`CONTRIBUTING.md` documents the sign-off. The PR checklist includes attribution and DCO checks. This supersedes the
co-author trailer rule previously in ADR 0019.
