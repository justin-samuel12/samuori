# Development Roadmap

Status: **Living document.** The whole product is one initiative (D31); milestones are dependency-ordered and
independently testable, not scope cuts. Update task status in the same PR that does the work.

## Current position

- **Configuration export and import (2026-10-29, owner request, ADR 0069).** `GET /configuration/export` gives an
  organization administrator the configuration as one `kind: Configuration` YAML (or JSON) file without secrets:
  policies, build methods and providers, recipe decisions and custom recipes, worker pools, registries, credential
  names, destinations, notification channels and rules, sign-in and audit settings, and the teams rules refer to;
  schema `api/schemas/configuration.v1alpha1.json`, deterministic order, audited. `POST /configuration/import`
  previews by default (create, update, unchanged or skip per item, and what needs attention) and with `dryRun=false`
  and an `Idempotency-Key` applies it in dependency order through the existing service functions, never deleting
  and never creating users, role bindings, secrets or projects; credentials and secret-bearing channels are listed for
  re-entry ([guide](operators/configuration-export.md)). Administration → Export & import in the portal (added to the
  screenshot tour, screenshot not yet captured) and `samuori config export|import [--apply]`. Runnable: API, CLI and
  UI; SEC-CFG-01 (`TestConfigurationExportImport`) passes on SQLite. Not yet run: PostgreSQL, a browser check of the
  page, an import between two separately installed servers.
- **Developer journey (2026-10-29, usability review).** A finished build shows a **Next step** card (Publish image
  for those allowed, otherwise who can; Open image, Download image, Deployment files; for failed, timed-out or
  blocked builds the cause, links to the log and attempts, and Build again). Images are named by app and version
  (`shop · 2026-10-29.1`) with the short digest beside them, in lists, titles and breadcrumbs. Digests, IDs, worker
  and raw isolation values sit under a collapsed **Technical details**; states read as badges with plain labels;
  "Build settings v1" replaces "Spec revision". The wizard's step list marks done, current, not reached and
  needs-attention steps, and YAML editing moved to **Advanced: edit as YAML** on the Review step. Breadcrumbs show
  project names; the Projects context bar no longer repeats its name; wizard routes highlight New image; New image
  with one usable project opens its wizard; the upload page has a drop zone with the server's limits. Runnable: UI;
  `display.test.ts`, `nav.test.ts` and `exclude.test.ts` pass. Not yet checked in a browser; the acceptance specs
  were updated but not rerun.
- **Screenshots (2026-10-28, owner request).** `make screenshots` captures every scene in `ui/e2e/tour/scenes.ts`
  (sign-in, developer and administrator screens, light and dark, 1440×900) from a throwaway local server with
  example data; the README shows a selection from `docs/screenshots/` and the [wiki gallery](https://github.com/justin-samuel12/samuori/wiki/Screenshots) every screen;
  `make screenshots-check` in `make ci` fails on a route without a scene ([local-dev](developers/local-dev.md#screenshots)).
  States only a worker produces are written into the throwaway database by the tour's seed. Runnable on macOS and
  Linux with the UI's Playwright Chromium; not run in GitHub CI.
- **Specs suggested by the server (2026-10-28, owner request).** `GET /snapshots/{snapshotId}/spec-suggestions`
  (developer, maintainer) derives starting specs from the newest completed discovery as the wizard does: built-in
  recipe specs per application, frontend and backend pairs, each Dockerfile, Railpack and Buildpacks when allowed,
  recommended first, each with canonical YAML and JSON, reasons, warnings and validation issues
  ([Suggested specs](architecture/buildspec.md#suggested-specs)). `samuori spec init --snapshot` writes the
  recommendation (or the first for `--method`, now including `recipe`), keeping the plain starters as fallbacks. The
  Go derivation and the wizard's are checked against one fixture. Runnable: API and CLI; `TestSuggest`,
  `TestSuggestMatchesWizard`, `TestSpecSuggestions`, `TestCLI` and `model.test.ts` pass on SQLite. Not yet run:
  PostgreSQL, a real worker build of a suggested recipe spec.
- **Consistent API (2026-10-28, owner request, ADR 0066).** Every list takes `limit` and `cursor` and returns
  `nextCursor` (50 lists added; nine bounded ones allowlisted), with stable ordering; lists that used to be complete
  still are without `limit`. Every create accepts `Idempotency-Key` (36 added as optional, replayed through the
  operations record as `409 idempotent_replay`); every non-2xx is documented with `Problem`, every `429` with
  `Retry-After`. Additive, nothing deprecated (`docs/developers/api-changelog.md`). The CLI follows `nextCursor`.
  Runnable: API, CLI and UI; `TestContractConsistency`, `TestCreateIdempotencyKeyReplays` and
  `TestPaginationOfWholeLists` pass on SQLite. Not yet run: PostgreSQL. Open: request bodies are inconsistent about
  unknown fields (61 reject them, 59 accept them); not changed because rejecting is breaking.
- **Seamless session renewal (2026-10-28, owner request, ADR 0068).** Before the maximum session ends, the portal
  shows "Your session ends at HH:MM. Renew it to keep working." (ten minutes ahead); **Renew session** asks for the
  password (local and LDAP) or continues with the OIDC provider. `POST /auth/session/renewal` re-authenticates the
  session's own user under the sign-in rate limit and lockout and replaces the session with a new ID, CSRF token and
  deadlines in one transaction (audited `session.renew`); the maximum still bounds each session. OIDC sign-in and
  renewal return to the page they started from through a server-validated same-origin `returnTo` (migration 00072).
  Runnable: API and UI; SEC-AUTH-13 (`internal/auth/renewal_test.go`, `internal/api/session_renewal_test.go`) and
  `ui/src/session/renewal.test.ts` pass on SQLite. Not yet run: a browser check of the dialog, a real OIDC provider,
  LDAP renewal against a directory, and PostgreSQL.
- **API usable from outside the repository (2026-10-28, owner request, ADR 0066).** The server publishes its
  contract at `GET /api/v1/openapi.yml` and `/openapi.json` to any signed-in caller (ETag, private caching); Help →
  API reference renders it with search, roles, parameters, schemas, the error format and curl examples for API
  tokens; operations marked `deprecated: true` with dates answer with `Deprecation` and `Sunset` headers; stability
  rules, `docs/developers/api.md` and `docs/developers/api-changelog.md` added. Runnable: API and UI;
  `TestContractIsServedToSignedInCallers`, `TestDeprecationHeadersOnlyOnMarkedOperations`,
  `TestDeprecationDatesAreChecked` and `ui/src/help/apiref.test.ts` pass. Not yet run: a browser check of the page.
- **Developer-friendly CLI (2026-10-28, owner request).** `samuori` covers the whole workflow: `login`/`logout`/
  `profiles` store a URL and a token checked with the server (read from standard input or a hidden prompt, never a
  flag) in `${XDG_CONFIG_HOME:-~/.config}/samuori` at mode 0600, with flags over environment over profile and a
  profile's token used only for its own URL; `projects create|list|show|rename|archive`, `analyze`, `spec
  init|list|show|validate|check|apply`, `builds`, `logs --follow`, `cancel`, `images`, `download`, `deploy-files`,
  `promote`, `requests`, `request repository|base-image|egress`, `withdraw`, `pipelines`, a generic `api
  OPERATION_ID` over the embedded contract, a one-step `ci`, and `completion`. Projects and specs resolve by name or
  ID; lists print tables, `--json` prints API objects. Existing commands, flags and exit codes are unchanged except
  that `projects` prints a table instead of tab-separated pairs. Runnable: `go test ./internal/cli` and `TestCLI`
  (live server, service identity token; one success and one refusal per group; `ci` with a blocked build exits 1 and
  with a finished build writes deployment files) pass on SQLite. Not yet run: against a real worker build,
  `promote` and `publish --wait` to a live registry, and the hidden prompt on a real terminal.
- **Editable infrastructure administration (2026-10-28, owner request).** Nodes & workers deletes pools that never
  had workers (otherwise offers to disable), lists, adds and deletes locations (refusals name the pools, projects or
  federation route that use them; no rename API), and lists and revokes unused worker join codes
  (`GET`/`DELETE /enrollment-tokens`, migration 00069). Federation disables peers, revokes grants and deletes peer
  locations (`DELETE /federation/routes/{id}`); peer endpoint and pin stay immutable, replaced by adding a new peer.
  Notifications deletes channels (`DELETE /notification-channels/{id}`, 409 while rules use them). All administrator
  only and audited. Runnable: API and UI; `TestEnrollmentTokenRevocation` and `TestInfrastructureDeletes` pass on
  SQLite. Not yet run: PostgreSQL and a browser check of the new dialogs.
- **Editing and removing (2026-10-28, owner request, ADR 0062).** Maintainers and administrators rename a project in
  its team; administrators set its build locations from the project page (shown once a second location exists); the
  requester or a project maintainer withdraws a pending repository, base-image, egress-access or secret-binding request
  (state `withdrawn`, audited; decided requests stay immutable); administrators edit pipelines (name, repository,
  refs, spec revision, username, write-only token; webhook kept) and delete them while no run is queued or fetching
  (runs kept); conversions are renamed and deleted (creator or maintainer; not while a run is active). Migration
  00070. Runnable: API and UI; focused API and service tests pass on SQLite. Not yet run: PostgreSQL and a browser
  check.
- **Editable people and access (2026-10-28, owner request, ADR 0065).** Administrators rename and delete unused
  teams, edit display names, disable and re-enable users (sessions and tokens revoked), reset local passwords to a
  shown-once temporary password the user must replace at sign-in, change a role in one step, rename service
  identities and delete identity providers nobody signed in through; people edit their own name and change their own
  password from Account. Runnable: API and UI; `internal/api/people_test.go` (SEC-AUTH-12) passes on SQLite. Not yet
  run: PostgreSQL and a browser check of the new dialogs and the forced password change.
- **Project archive, restore and purge (2026-10-28, owner decision, ADR 0058).** Maintainers and administrators
  archive a project (hidden from lists, new work refused with 409, grants revoked and audited, queued and running
  builds cancelled) and restore it without its grants; administrators purge an archived project with its typed name,
  which deletes its stored files and keeps its records and audit trail. Runnable: API and UI; `TestProjectArchiveRestorePurge`
  and the `can` test pass on SQLite. Not yet run: PostgreSQL, a browser check, and a purge with a real worker's
  images or a remote blob store.
- **Deprecating and withdrawing built-in runtimes (2026-10-28, owner decision, ADR 0060).** Organization
  administrators deprecate (builds warn), withdraw (hidden from developers, refused at admission with the reason;
  ranges resolve to the newest runtime still available) or approve again one runtime a built-in recipe version ships,
  stored per organization (migration 00068) and audited. A same-label organization runtime stays shadowed. Runnable:
  API and the Runtimes dialog; `TestShippedRuntimeStatus`, `TestShippedRuntimeStatusAPI` and the `can` test pass on
  SQLite. Not yet run: PostgreSQL, a browser check of the dialog and New image, and a worker build.
- **Policy and recipe editors (2026-10-28, owner request).** Registries & Recipes > Build policies edits the
  `frontends`, `build-args`, `validation` and `sensitive-content` policies (add, edit and remove entries; dry run,
  confirmation with reason, `If-Match`); `GET /policies` reports `updatedBy`. Organization runtimes get a Duplicate
  action that saves a new draft; custom recipe drafts can be discarded (`DELETE /custom-recipes/{id}/versions/{v}`,
  administrators, audited, 409 for non-drafts). Runnable: API and UI; `TestCustomRecipeLifecycle`,
  `TestCustomRecipeAPI` and the policy-helper node test pass on SQLite. Not yet run: a browser check of the editors
  and PostgreSQL.
- **Editable secrets and registries (2026-10-28, owner request, ADR 0064).** Administrators edit secret grants in
  place (widening keeps bindings; narrowing disables the bindings that no longer fit, audited, with a warning before
  saving), edit allowed secrets' label and note, rotate bindings, edit and delete image sources (409 while an
  unfinished build plans to pull through one) and retire signing keys from the portal. Runnable: API and UI;
  `TestUpdateGrant`, `TestUpdateAllowedSecret`, `TestUpdateAndDelete` and `TestSecretAndImageSourceEdits` pass on
  SQLite. Not yet run: PostgreSQL, a browser check, and a grant edit against a live external store.
- **Name and brand (2026-10-27, owner decision, ADR 0057).** The logo and palette come from `docs/brand/`; the UI
  loading indicators animate the mark.
- **Deployment files (2026-10-28, owner request, ADR 0059).** Next to "Download image", the build page and the Images

  publication when there are several) or the local `docker load` name. Runnable: the API and UI; focused tests pass;
  samples pass `docker compose config` and Helm 3.16.3 lint and template. Outstanding: a real `docker compose up` and
  `helm install`, and a browser check of the dialog.
- **Project deployment files (2026-10-28, owner request, ADR 0061).** The project page offers one `compose.yml` and
  one Helm chart for all of the project's images, with a build and publication choice, replicas, links (an env var set
  to another image's in-network URL) and volumes per image; images without a successful build are listed and left
  out. Runnable: API and UI; focused tests pass; a sample passes `docker compose config`. Outstanding: real Helm
  lint/install, `docker compose up`, and a browser check of the dialog.
