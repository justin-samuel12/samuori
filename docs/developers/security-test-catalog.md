# Security Test Catalog

Status: **Living document.** It maps every test ID in the threat model
([`../architecture/threat-model.md`](../architecture/threat-model.md)) to a planned implementation and a milestone
gate.

> **All tests were removed on 2026-10-20 by owner directive (ADR 0039); focused regression tests for critical
> boundaries were restored the same day (ADR 0039, amendment).** Rows not marked restored are **not
> implemented**: the files in "Planned location" no longer exist, and no mitigation is verified. Each row keeps the
> result last recorded before the removal, prefixed "before removal". Those runs happened at earlier commits and
> cannot be reproduced from the current tree.

## Rules

- A mitigation counts as **implemented** only when every catalog test for it exists, passes in CI, and the
  milestone gate below includes it. A documented mitigation alone is **specified**.
- Each test carries its ID as the subtest name: `t.Run("SEC-UPL-01", ...)` in Go, or the test title in Playwright.
  No automated check yet matches catalog IDs to test names.
- A milestone cannot be marked done in `docs/roadmap.md` while any test gated on it is not `passing`.
- Rows whose Threats column says "Functional" are positive tests that security designs depend on (for example
  byte-exact binary secrets). They are gated like the others.
- Status values: `not implemented` → `implemented` (test exists) → `passing` (green in CI, with a link to the run).

ID prefixes: `SEC` security boundary, `CHA` failure and recovery, `INT` integration. Tests are colocated `_test.go`
files in the package they cover (ADR 0039 as amended), not separate suites.
